# A résumé-ready address

You do not need to buy a domain to demonstrate this project. A publicly accessible
project on a standard hosting subdomain can work. A personal domain gives you a
reusable address for a portfolio and future projects.

## Suggested route

1. Choose an available personal domain based on your name. Register it through
   a domain registrar and review the yearly renewal price before buying. No name
   has been checked for availability, and no domain has been bought for you.
2. Put the project repository on your GitHub account when you are ready to share
   the source. It is currently committed locally on the Desktop.
3. Deploy the static frontend to a host such as Vercel or GitHub Pages. The site
   files are in `heat-lineup-lab/dist/`; there is no frontend build step.
4. Add the purchased domain to that hosting project. Enter the DNS records the
   host provides in the registrar's dashboard and wait for verification/HTTPS.
5. Test the final demo link in a private browser window without signing in before
   putting it on a résumé. Link both the demo and the project source, and describe
   the implemented work accurately: interactive lineup comparisons using observed
   advanced player profiles. Prediction modeling and AI reports are future work.

The existing Sites deployment is private. A custom address by itself does not
remove its access controls. No hosting migration, domain purchase, or audience
change has been made as part of the branding update.
